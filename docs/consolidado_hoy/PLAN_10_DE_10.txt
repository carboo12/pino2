B. OTROS PROBLEMAS REALES DETECTADOS
============================================================

1. SQL EN STRINGS (SQL Injection potencial)
   - sales.service.ts, orders.service.ts, etc. usan template literals
     con valores interpolados. Usan parametros $1,$2 pero hay riesgo
     en la construccion de queries dinamicas.

2. SIN FUNCION HELPER COMPARTIDA
   - La logica bultos/unidades esta duplicada en 6+ archivos del backend
   - Cada servicio recalcula Math.floor(stock/upb) por su cuenta
   - Un cambio en la regla = editar 6+ archivos

3. TESTS INSUFICIENTES PARA BULTOS/UNIDADES
   - stock-display.test.tsx: 6 tests de formateo (solo web)
   - sales.service.spec.ts: 3 tests con units_per_bulk pero basicos
   - No hay test de integracion que valide:
     * Crear producto con handles_bulk=true
     * Hacer venta con bultos+unidades
     * Verificar movimiento con snapshot correcto
     * Verificar que stock_bulks/stock_units GENERATED coinciden

4. CI NO CORRE REALMENTE
   - El workflow ci-mvp.yml referencia seed_test.sql que no existe
   - Flutter job depende de flutter-action@v2 pero no se ha validado
   - No hay step de coverage

5. WEB: NO HAY VALIDACION DE handlesBulk EN FORMULARIOS
   - edit-product-page.tsx: stockBulks/stockUnits son readonly (bien)
     pero NO hay toggle/checkbox para cambiar handles_bulk
   - No se puede crear un producto como "maneja bultos" desde la web

6. FLUTTER SIN COMPILAR
   - No se ha corrido flutter build apk
   - No se sabe si compila con los cambios recientes
   - handlesBulk no existe como campo en el modelo Flutter
