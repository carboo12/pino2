17.1 Objetivo operativo obligatorio

Implementar una cadena única y trazable:

  ADMIN/JEFATURA WEB
      -> crea ruta comercial
      -> asigna clientes al Gestor
      -> Gestor sincroniza ruta
      -> Gestor visita y levanta preventa offline
      -> Bodega consolida pedidos
      -> Auxiliar prepara/carga mercancía
      -> Jefatura asigna carga al Rutero
      -> Rutero acepta físicamente la carga
      -> Rutero entrega, cobra y emite comprobante
      -> Rechazos quedan como devolución en tránsito
      -> Rutero retorna mercancía y efectivo
      -> Jefatura revisa y cierra liquidación

REGLAS NO NEGOCIABLES DEL FLUJO:

[ ] El Gestor de Ventas nunca puede ver “todos los clientes” como fallback.
[ ] El Gestor sólo ve clientes asignados a su ruta/fecha.
[ ] El Gestor no se autoasigna clientes.
[ ] El Rutero sólo ve cargas y entregas asignadas a su usuario.
[ ] El Rutero no escoge pedidos libres.
[ ] Crear una ruta no modifica inventario.
[ ] Crear una carga planificada no descuenta inventario.
[ ] Toda salida, transferencia, entrega, rechazo y retorno tiene movimiento.
[ ] Bultos y unidades se convierten siempre a unidades base:

      total_units = (quantity_bulks * units_per_bulk_snapshot)
                    + quantity_units

[ ] El factor units_per_bulk usado queda congelado por línea.
[ ] Un reintento offline con el mismo externalId no duplica pedido, visita,
    cobro, devolución, entrega ni cierre.
[ ] Precios, totales, crédito y saldo se validan/recalculan en NestJS.
[ ] La factura/ticket al cliente usa sales + sale_items.
[ ] No usar invoices para factura de cliente: invoices es compra a proveedor.
[ ] Una devolución rechazada en calle no vuelve inmediatamente al stock de
    bodega; permanece EN_TRANSITO hasta recepción física.
[ ] La liquidación sólo cierra cuando cuadran mercancía, entregas, cobros y
    devoluciones, o queda una observación explícita.

17.2 Mapeo funcional de roles Trello a roles existentes

No crear nombres nuevos dispersos. Para el MVP usar:

- Administrador General:
  master-admin.

- Jefe / Encargado de Bodega Central:

seguir llamándose vendor_id, pero el contrato nuevo debe exponer assigneeUserId
o salesManagerId para evitar que el nombre de columna determine el negocio.
